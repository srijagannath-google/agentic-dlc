# Spec-Driven Development (SDD) Governance, Living Lifecycle & Dual-Plane Human Review

`agentic-dlc` treats `specs/application_spec.md` + `design/solution_design.md` as a **living, hash-pinned executable contract** rather than a write-once Waterfall BRD, while giving humans full visibility, traceability, and sign-off control whether an enterprise ALM board (Jira / Azure DevOps) is connected or not.

---

## 1. Eight Universal SDD Invariants

1. **Contracts Before Implementation Slices (Contract Isolation):** Database DDL (`src/db/schema.sql`), OpenAPI (`src/contracts/openapi.yaml`), and `data-testid` contracts are isolated in foundational technical slices (`US-TECH-*`) that precede dependent backend service and UI slices via `dependsOnStories`. Never mix schema/contract definition with downstream UI implementation in the same atomic slice.
2. **3D Small-Slice Bounds & Mandatory Unit-Test Co-Location:** Scope every implementation slice to `<= 3` production files, `<= 400` lines of implementation code (`<= 600` total with tests), and `<= 2` directly affected unit-test targets (`scopeBounds`). Ban compound `"and"` slices joining unrelated views or subsystems, and **always co-locate unit tests in the same slice** (never defer unit testing to a separate "write tests later" story). Fibonacci `storyPoints` (`1..8`) are optional PMO metadata, never a substitute for 3D slice bounds.
3. **Thin-Pointer ALM Work Items (Zero Spec-to-Ticket Drift):** `specs/application_spec.md` is the **single source of truth** for business rules, roles, and state transitions. Jira / Azure DevOps stories carry a concise slice summary, end-to-end traceability matrix, and `specPointer` (`specPath`, `specSha256`, `sectionAnchors`) — never a diverging prose rewrite of specification formulas.
4. **4-Part Runnable Verification Contract & UI Reachability Gate:** Every slice specifies `verificationPlan` with (1) Checkout/Patch Command, (2) Build/Execution or Dev-Server Command, (3) Target URL or Surface, and (4) Concrete Steps, Expected Outcomes & Artifact Capture — or `N/A — <specific non-runnable contract rationale>` for pure schema/library contracts. Bare `"N/A"` and browser UI steps targeting unmounted views are prohibited.
5. **Living Spec Lifecycle, Phase `N+1` Delta Mode & Completed-Slice Compaction:**
   - Lifecycle states: `🟡 IN REVIEW` → `🟡 IN PROGRESS` → `🟢 COMPLETED` (plus `⚪ SUPERSEDED` and `🟢 COMPLETED (Retro-Spec)`).
   - **Phase `N+1` Delta Mode (`--mode delta`):** Appends new capability phases in-place while enforcing **byte-for-byte preservation** of prior completed phases/slices, historic tracking IDs, and historic `* **Approvals:**` sub-bullets (`lint_spec_structure.py --baseline-spec`).
   - **Context Compaction:** Once a slice reaches `Done`, verbose execution scaffolding compacts to a 1–2 sentence `compactedContext` (`- **Context:**`) summary (`alm_jira_ado_bridge.py --action compact-completed`) so multi-wave living specs never suffer context-window rot.
   - **Retro-Spec Mode (`--mode retro-spec`):** Reverse-engineers an existing production codebase into a verified `🟢 COMPLETED` 5-Pillar Living Specification with **Zero Backlog / Zero Child Ticket Creation Guarantee**, onboarding brownfield apps into SDD governance before future delta enhancements.
6. **Narrative Conciseness & Codebase Referential Audit:** Non-table narrative prose in `specs/application_spec.md` stays within the SDD word-count budget (`<= 3,500` prose words; rules live in parsed `§3.3`/`§3.4`/`§3.5`/`§4.2` tables, including optional `Examples` input→output test vectors in `§3.4`), and `lint_spec_structure.py --check-codebase` verifies cited repository paths exist.
7. **3-Tier Spec Deviation Negotiation Protocol:**
   - **Tier 1A (In-Scope Polish / Bug Fix):** Apply code + co-located unit-test fix directly within slice bounds.
   - **Tier 1B (Spec / Contract Deviation Challenge):** If fixing an issue or honoring review feedback requires altering an endpoint, schema table, `§3.3` state transition, or `§3.4` `BR-NN` rule, **HALT BEFORE EDITING `src/`**, post `⚠️ Spec Deviation Detected` naming the conflicting Spec section, obtain explicit human confirmation, and **atomically update `specs/application_spec.md` + `design/solution_design.md` + `src/` + tests** (`--refresh-from-stage`).
   - **Tier 3B (Automated Suggestion Violating Negative Spec Constraint):** Reject automated suggestions that violate explicit RBAC, state-guard, or zero-leak constraints in `specs/application_spec.md`.
8. **Multi-Layer Human Attribution, Bot Exclusion & Regulated Two-Person Review:** Exclude all bot/agent identities from human approval lists; track `originalAuthor`, `pairCollaborators` (reviewers who steered architecture/code receive dual credit in both `approvers` and `pairCollaborators`), `approvers` (`>= 2` distinct humans required on `regulated` ceremony track), and `manuallyVerifiedBy` across `specs/application_spec.md` (`* **Approvals:**`) and `specs/gate_approvals.json`.

## 2. Dual-Plane Human Review & Approval Patterns

| Review Plane | When Used | How Humans Review & Approve Specs (Gate 2 / 4A) | How Humans Review, Track & Approve Stories / Slices (Gate 3 / 5 / 6) |
| :--- | :--- | :--- | :--- |
| **Pattern A: Enterprise ALM + Git (`alm-and-git`)** | `almPlatform` is `ado` or `jira` | Review **1-Page Executive Gate Decision Brief** (`specs/gate_briefs/gate_2_spec.md`, answering the 5 Structured Questions) + inline PR/CL diff of `specs/application_spec.md` linked to a Parent Epic/Feature; approve via PR + `gate_tracker.py --action approve --approvers ...` | Inspect dependency-chained, thin-pointer Stories (`dependsOnStories` → Jira `Blocks` / ADO `Predecessor`) on the live Sprint Board; watch automatic `To Do → In Progress → Done` transitions, `BUG-*` defect remediation comments, and record UAT sign-off (`--verified-by`) |
| **Pattern B: Git-Native Docs-as-Code (`git-pr-docs-as-code`)** | `almPlatform == "none"` with GitHub / GitLab / Azure Repos / Piper | Open a dedicated **Spec & Contract Pull Request** governed by `CODEOWNERS` / `OWNERS`; CI runs `lint_spec_structure.py --strict-approvals` verifying human usernames in `* **Approvals:**` (`>= 2` humans if `regulated`); merging the PR is the auditable approval | Track slices via the `## Execution Roadmap` checklist (`- [ ]` → `- [x]`) and **Atomic Per-Slice PRs** (`[<DomainSlug>][US-FUNC-01] - <Title>`) whose PR body answers the **5 Structured Questions** (`1. Goal`, `2. Big Picture`, `3. Spec Plan Adherence`, `4. Verifier Focus`, `5. Reviewer Focus`) and compacts completed tasks in the same commit |
| **Pattern C: Interactive Gate Briefs (`interactive-briefs`)** | Local / solo / rapid prototype (`ceremonyTrack == "quick"`) | Review rendered `specs/gate_briefs/<gate_id>.md` Decision Brief + open questions directly in IDE/chat | Approve gate via chat reply bound to `artifactSha256` in `specs/gate_approvals.json` |
