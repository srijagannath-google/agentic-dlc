# Pluggable MCP Modernization Domain Packs (`specs/project_setup.json#domainPacks`)

`agentic-dlc` remains a **100% domain-neutral, zero-dependency lifecycle orchestrator**. When a modernization estate involves specialized legacy runtimes (mainframe COBOL/JCL/VSAM, commercial RDBMS dialects, data warehouse SQL, or Hadoop/Oozie batch workflows), Stage 0 (`00-setup-and-connection`) records active `domainPacks` in `specs/project_setup.json` so Stages 1, 4A, and 5 invoke external compiler-grade MCP servers or CLI translators rather than relying on heuristic LLM translation alone.

## Supported Domain Pack Identifiers

| Pack Identifier | Target Workload | Stage 1 Discovery Hook | Stage 4A Architecture & Contract Hook | Stage 5 / 6 Implementation & Parity Hook |
| :-- | :-- | :-- | :-- | :-- |
| `mainframe-mat` | IBM z/OS / AS400 COBOL, Copybooks, JCL, CICS, BMS screens, VSAM, DB2 | Parse COBOL `COPY`/`CALL` graphs and BMS screen maps; extract packed-decimal (`COMP-3`) field precision and batch JCL job chains into `specs/discovery_architecture_and_inventory.md` + golden I/O cases into `test/legacy_parity_goldens.jsonl`. | Map stateful CICS pseudo-conversational flows to stateless REST/gRPC contracts; isolate copybook/EBCDIC translation inside `deploy/coexistence/` if running phased Strangler waves. | Enforce fixed-point `Decimal` arithmetic (`BR-*` `@dlc-rule` annotations) and validate numerical parity via `TC-PARITY-*` test cases. |
| `cloud-dms` | Oracle PL/SQL, SQL Server T-SQL, Sybase, DB2 LUW → PostgreSQL / Cloud SQL / AlloyDB / Spanner | Inventory stored procedures, triggers, sequences, synonyms, and proprietary data types in Stage 1 `§2.1`. | Use Google Cloud Database Migration Service (DMS) conversion workspaces / dialect rules to design the normalized 3NF DDL (`design/solution_design.md §1.2`) and CDC replication topology (`design/data_migration_and_cutover.md`). | Promote business-logic triggers out of database stored procedures into explicit, testable application-service guards (`@dlc-guard`) while keeping referential integrity in SQL DDL. |
| `bqms` | Teradata BTEQ, Netezza, Snowflake, Redshift, HiveQL → BigQuery | Extract upstream/downstream lineage, partitioning keys, volatile staging tables, and UDF dependencies into `specs/dependency_dag.json`. | Invoke BigQuery Migration Service (`bqms`) batch SQL translation rules for target analytical views/pipelines in `design/data_architecture.md`. | Verify row-count, null-handling, and aggregate rounding parity against `test/legacy_parity_goldens.jsonl`. |
| `hadoop-oozie-flink` | Apache Oozie XML DAGs, Hive/Pig scripts, Spark RDDs, Flink 1.x → Cloud Composer (Airflow) / Dataproc Serverless | Convert Oozie `<action>` / `<fork>` / `<join>` XML nodes into topological tiers in `specs/dependency_dag.json` and document SLA windows. | Design idempotent, backfill-safe DAG tasks and dead-letter handling in `design/integration_architecture.md`. | Implement modular task operators with deterministic retry/idempotency keys and hermetic local test fixtures. |
| `agentic-audit` | Existing GenAI / Agentic apps (LangChain, ADK, Vertex AI, MCP servers) | Audit prompt templates, tool schemas, memory stores, and unguarded tool-call side effects. | Enforce OWASP Top 10 for LLM/Agentic Apps in `design/security_architecture.md` (tool-parameter authorization, prompt-injection boundaries, human-in-the-loop confirmation for mutating tools, and `A2UI v0.9` structured rendering). | Verify deterministic tool-guardrail enforcement and structured citation rendering in Stage 6. |

## Invocation Rule

1. **Optional & Graceful:** Domain packs are strictly opt-in (`specs/project_setup.json#domainPacks`). When an external MCP tool for a configured pack is connected in the host IDE/CLI, prefer its deterministic AST/SQL/mainframe parser output over regex heuristics; when no MCP server is attached, fall back cleanly to built-in `scan_input_sources.py` + `specs/dependency_dag.json` analysis and note the fallback in the Gate 1 brief.
2. **Clean Target Invariant Preserved:** Even when a conversion tool produces a 1:1 Mechanical translation of legacy tables (`TBL_CUST_MSTR`), Stage 4A **must** still normalize target `src/` contracts into clean domain nouns and isolate any temporary legacy schema translation inside `deploy/coexistence/`.
